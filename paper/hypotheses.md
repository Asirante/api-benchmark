## 가설 1 — 간헐적 붕괴의 원인은 아키텍처가 아니라 커넥션 풀 크기다: **지지**

기준 조건(풀 500:100, 640 rps, 180초, 아키텍처별 3회)에서 붕괴가 재현되어 세 아키텍처 모두 판정 대상이 되었습니다(REST 1/3, GraphQL 2/3, gRPC 1/3 + 포화 1회). 같은 부하에서 풀만 줄이면 붕괴가 사라집니다. 풀 20:20·50:50·100:100 의 **27회 실행 전부 안정**이었고 목표 640 iter/s 를 100% 달성했으며 p99 는 2.5~8.4 ms, DB CPU 스로틀링은 1.7% 이하, ProcArray 대기는 0 이었습니다. 반면 풀 500:100 의 붕괴 실행은 새 DB 연결 6,995~10,137개, ProcArray 대기 273~400 세션, DB 스로틀링 96~99.7%, p99 892~1,212 ms 를 보였습니다. 800 rps 포화 구간에서도 사전 고정 규칙(작은 풀 최선값이 500:100 대비 처리량 +10% 이상 & 3회 범위 비중첩 & p99 더 낮음)을 세 아키텍처 모두 충족했습니다(REST +41.9%, GraphQL +35.2%, gRPC +46.5%). 연결 반복 생성과 동시 세션 상한을 분리한 500:500 조건은 REST 차이 없음, GraphQL 불확실, gRPC 확인으로 일관되지 않았고, 640 rps 에서 500:500 도 무너졌습니다. 따라서 **주 원인은 동시 세션 상한이 큰 것**이며, 연결 반복 생성은 조건에 따라 더해지는 요인으로 해석합니다.

한계: 붕괴는 확률적으로 나타나므로(기준 조건 9회 중 5회) 붕괴 유무 자체는 이진 판정이 아니라 발생 빈도로 읽어야 합니다. 또한 같은 풀 500:100·480 rps(용량의 약 70%)에서는 9회 모두 안정이어서, 붕괴는 **큰 풀 + 용량에 가까운 부하**가 겹칠 때 나타났습니다. 직전 세션(`exp_20260915_030551`)의 포화 전 붕괴 3건이 모두 호스트 swap 구간에 몰려 있었다는 점(swap 없는 31회 중 0건, swap 발생 5회 중 3건)도 함께 기록합니다.

## 가설 2 — GraphQL 의 열위는 프로토콜이 아니라 TC3 의 쿼리 수 때문이다: **p99 에 대해 지지, 처리량에 대해서는 해당 없음**

붕괴 영향을 배제한 풀 50:50 에서 GraphQL 의 반복당 DB 쿼리를 24회에서 19회(REST·gRPC 와 동일)로 맞추자, 사전 고정 규칙(p99 30% 이상 감소 & 3회 범위 비중첩)을 두 부하에서 모두 충족했습니다. 640 rps 에서 p99 4.6 ms[3.9–6.0] → 2.6 ms[2.4–2.6](−45%), 800 rps 에서 79.8 ms[68.1–96.9] → 44.3 ms[42.5–47.5](−45%)입니다. 같은 세션의 REST p99 는 36.6 ms, gRPC 는 79.1 ms 였으므로, 보정 후 GraphQL 은 REST 에 근접하고 gRPC 보다 낮습니다. 경로는 DB 작업량입니다. DB CPU 가 147% → 123%(800 rps)로 줄었고 DB 스로틀링은 두 조건 모두 1% 이하였습니다.

처리량 측면에서는 판정할 차이가 없었습니다. 두 조건 모두 800 iter/s 를 100% 달성했고, 이 구간에서는 세 아키텍처 모두 **API 컨테이너 CPU 가 제한(2코어)에 걸려** 있었습니다(스로틀링 약 99%). 다만 처리 한계 실험에서는 GraphQL 이 900 rps 부터 목표 미달(달성 784~821 iter/s)로 REST·gRPC(약 1,000 iter/s)보다 낮았는데, 이는 반복당 쿼리 24회에서 비롯된 **API·DB 처리 비용 차이**와 방향이 같습니다. 쿼리 수를 맞춘 조건으로 처리 한계를 재측정하지 않았으므로, "쿼리 수를 맞추면 처리 한계도 같아지는가"는 **보류**입니다.

주의: 800 rps 의 p99 는 세션 간 변동이 큽니다(GraphQL 기존 조건이 `de_20260916_1154` 에서는 170 ms, `de_e2_20260917_1243` 에서는 79.8 ms). 따라서 가설 2 판정은 같은 세션 안의 비교로만 수행했고, 논문에서도 800 rps p99 의 세션 간 비교는 피해야 합니다.
