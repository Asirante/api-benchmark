벤치마크 통합 가이드

manage.sh 스크립트 사용법부터 CSV 데이터 엑셀 분석까지 한 번에 마스터하기

단축 명령어(bm) 설정하기 최초 1회 필수

매번 ./manage.sh test-all 2000 치기 귀찮으시죠? 아래 명령어를 한 번만 실행하면 앞으로는 bm 두 글자만 쳐서 스크립트를 실행할 수 있습니다.

1

터미널에 아래 명령어를 복사해서 붙여넣고 엔터를 칩니다:

./manage.sh setup-alias
2

스크립트가 알려주는 source ~/.bashrc (또는 zshrc) 명령어를 터미널에 한 번 더 입력합니다.

설정 완료! 이제부터는 bm start처럼 짧게 사용하세요.

퀵 스타트 바쁘면 이것만 보세요

Step 1
서버 켜기
bm start
Step 2
테스트 실행 & 데이터 추출
bm test-all 2000

표준 및 프록시 테스트가 차례로 돌고 KST 시간 기준의 CSV가 자동 생성됩니다.
(※ 스파이크 테스트는 제외)

Step 3
서버 끄기
bm stop

명령어 사전

명령어 설명 사용 예시
bm setup-alias bm 단축키를 터미널 환경에 영구 등록합니다. ./manage.sh setup-alias
bm test-all [VUs] 추천기본 및 프록시 테스트 순차 실행 후 자동 추출 (TC8 제외) bm test-all 5000
bm test [VUs] 기본 아키텍처 비교(TC1~7)만 단독으로 실행합니다. bm test 1000
bm test-spike 스파이크 부하 테스트(TC8)만 단독으로 실행합니다. bm test-spike
bm export-csv 역대 저장된 모든 데이터를 엑셀용 CSV로 추출합니다. bm export-csv
bm export-csv - [VUs] 특정 인원수(VUs)로 테스트했던 데이터만 필터링합니다. bm export-csv - 1000
bm restart 서버 중지 후 강제로 새로고침(재시작)합니다. bm restart
bm clean 모든 컨테이너와 데이터베이스 볼륨까지 완전히 삭제합니다. bm clean
고부하 및 스파이크 테스트 시 주의사항

VUs 5000 이상의 고부하 테스트나 스파이크 테스트(TC8)가 돌아가는 동안에는 PC 자원 보호를 위해 유튜브 시청, 무거운 프로그램 실행 등을 자제해주세요. 벤치마크 결과에 왜곡이 발생할 수 있습니다.

CSV 데이터 관전 포인트

./csv_results/ 폴더에 생성된 파일들은 각각 시스템의 속도와 체력을 의미합니다.

http_req_duration.csv

grpc_req_duration.csv 포함

응답 속도 (Latency, ms)

클라이언트가 요청을 보내고 응답을 받기까지 걸린 시간입니다. 값이 낮을수록 좋습니다.

관전 포인트
  • • TC3 (Under-fetching): REST의 2번 호출 시간 합계 vs GraphQL의 1번 호출 시간 비교
  • • TC9 (프록시 오버헤드): Envoy를 거친 gRPC와 Direct gRPC의 지연 시간 차이

http_reqs.csv

공백 맞춤용

초당 처리량 (Throughput / TPS)

서버가 1초에 몇 개의 요청을 안정적으로 처리해냈는지를 보여주는 체력입니다. 값이 높을수록 좋습니다.

관전 포인트
  • • 스파이크 방어력 (TC8): 10,000명이 몰릴 때 처리량이 0으로 떨어지는(서버 다운) API는 무엇인가? (※ bm test-spike 단독 실행 시 확인 가능)

엑셀 피벗 테이블로 1분 만에 보고서 만들기

수만 줄의 CSV 데이터를 복잡한 함수 없이 피벗 테이블 4번의 클릭으로 요약하세요.

  1. 1

    CSV 열기 & 전체 선택

    http_req_duration.csv 파일을 엑셀로 열고 Ctrl + A를 눌러 전체를 선택합니다.

  2. 2

    피벗 테이블 삽입

    엑셀 상단 메뉴에서 [삽입] - [피벗 테이블]을 클릭하고 확인을 누릅니다.

  3. 3

    필드 배치

    우측 피벗 테이블 필드창에서 아래와 같이 드래그 앤 드롭 하세요.

    행(Rows) tc (TC1, TC2 등 시나리오 기준)
    열(Cols) api (rest, graphql, grpc 기준)
    값(Vals) value
  4. 4

    값 설정 변경 (가장 중요)

    값 영역에 들어간 'value'를 클릭하고 [값 필드 설정]에 들어가서 계산 방식을 '합계'가 아닌 평균(Average)으로 변경합니다.

🎉 위 4단계를 거치면 논문/보고서에 바로 복사해서 붙여넣을 수 있는
"시나리오별/프로토콜별 평균 응답속도 비교표"가 완성됩니다!
